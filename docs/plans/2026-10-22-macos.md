# Metronome for macOS

Bring the approved 1.5.0 instrument and practice tools to a self-contained Mac App Store application, sharing the existing UI, persistence model and beat timeline.

## Product and layout

- Keep the brand, single-screen graphic welcome, precise BPM display, beat semantics, existing sounds and shared motion tokens.
- Add a desktop presentation mode explicitly provided by the Mac application. Mobile and web keep their current presentation by default.
- At 840dp and wider, show a quiet 200dp navigation rail for Metronome, saved tempos, practice sets and Settings. Compact windows retain labeled navigation. Keep the instrument and forms at readable widths.
- Present existing tool sheets as centered, bounded, scrollable dialogs on Mac, with keyboard dismissal. Preserve the mobile sheet implementation and inset behavior.
- Support native menus, keyboard playback and tempo control without stealing text input, native backup file dialogs, resizable windows and system appearance.
- Omit settings for unsupported phone capabilities. Preserve their stored values for the mobile apps.

## Platform

Use Compose Desktop on JVM through a new `desktopApp` shell and `shared` desktop target. Bundle JBR 21 and all assets; require no separately installed Java, network connection, account or updater. The first package targets Apple silicon on macOS 13 or newer.

Provide desktop services through the existing interfaces and Koin. Use JavaSound with predecoded bundled PCM resources, a bounded audio queue, reusable output and explicit failure handling. Retain the shared absolute beat timeline and audio submission callback. Persist data inside the app's sandbox support directory and use user-selected file access for backups.

## Distribution

Use bundle ID `com.merkost.metronome`, existing App Store record `6761737690`, and developer team `P47X2292CM`. Prepare macOS version 1.5.0, build 1 independently of the published iOS release. Add the macOS platform to the existing listing and retain the approved public product identity.

Package with Compose's Mac App Store mode, app sandbox, a bundled runtime, signed native libraries, and existing Mac App Distribution and Installer identities. Production uses unrestricted sandbox entitlements without provisioning profiles. The optional TestFlight mode requires matching application/runtime profiles and their identifier entitlements. Do not add microphone, debugger or unnecessary network permissions. Capture actual opaque 16:10 desktop screenshots and supply accurate platform-specific metadata and privacy details.

Use the genuine `Metronome Mac` native application target in `desktopApp/macosXcode/MetronomeMac.xcodeproj` to archive the verified Compose application. Its staging script preserves the prepared payload while Xcode processes Info.plist, signs the staged app and creates archive metadata. Upload through Organizer using the existing Xcode developer account; no separate Transporter installation is required.
